# Build plan

The repository was empty. The supplied ZIP is a product handoff, not an existing application. Use dependency-free semantic HTML, CSS and small browser JavaScript. A Node build renders the content and offer configuration into initial HTML, then copies an explicit public asset allowlist into `dist/`.

Journey: hero → practical outcomes → actual sample pages → six content topics → included planner → main offer → optional companion → FAQs and final action. Navigation and sample links work without JavaScript; JavaScript enhances samples with a native modal. The main guide and bonus share a hero arrangement; the companion stays in its own section.

Use the brief as factual authority and adapt the supplied copy in `offer.config.json`. Use exact WebP covers, the three real sample pages and the responsive illustrative workspace photograph. Retain PNG masters as source, outside the build output.

Use forest, cream, ink and restrained gold; Georgia headings and system sans-serif body, generous whitespace, thin editorial rules and a flat-cover fallback on phones. Shared CSS drives an editable style tile.

Unknown prices remain null. Preview CTAs lead to useful page sections. Main checkout requires a complete, validated offer. The separate companion has its own gating. No deployment, tracking, accounts, email collection, payment backend or invented commercial details.

Validation: meaningful Node tests for incomplete/valid offers, unsafe URLs and independent companion gating; inspect the generated HTML and public files; inspect browser rendering and interactions where tools allow, at 320, 360, 390, 768 and 1440px and short landscape. Record measurements and limitations in QA and remaining commercial inputs in the launch checklist.
